Pipeline & ToolsPython · Blender add-onIn progress · build 1 of 3

Problem
Small mistakes slip through at export: unapplied scale, missing UVs, n-gons, off-convention names, textures that aren't power-of-two. Each one costs a round trip with the engine team.
Built for
A 3D artist handing assets to an engine. I'm interviewing an artist first and testing the tool with them after.
Approach
A side-panel add-on: one button scans the scene, lists every problem by object, and offers a one-click fix where the fix is safe. Rules live in one editable file so a team can set its own conventions.

Rendering & VisualsWebGL · GLSL · three.jsUp next · build 2 of 3

Problem
Turn a lit 3D scene into two-colour ink, in the spirit of 1-bit games, without the dot pattern crawling across surfaces every time the camera moves.
Built for
An art director tuning the look. They get sliders for threshold, pattern scale and edge lines instead of having to touch shader code.
Approach
Render the scene, then a full-screen pass that compares brightness against a threshold pattern. I'll compare ordered (Bayer) and blue-noise patterns, then test ways to keep the pattern stable under camera motion.

Environment & WorldBlender · Geometry NodesPlanned · build 3 of 3

Problem
Placing plants by hand is slow and looks placed: even spacing, grass on cliffs, trees in the middle of paths.
Built for
An environment artist who wants control through a handful of plain-language inputs, not a node graph.
Approach
A node group that scatters by rules: density falls off with slope and height, nothing grows within a set distance of a path curve, and larger plants push smaller ones away. Only the inputs an artist needs are exposed.
